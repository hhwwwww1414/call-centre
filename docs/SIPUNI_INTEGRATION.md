# Интеграция с Sipuni

Документация провайдера: https://doc.sipuni.com/articles/636--api/

Код: `lib/telephony/providers/sipuni.ts`. Переключение с демо-режима — одна
переменная `TELEPHONY_PROVIDER=sipuni`, остальной код не меняется.

## Что работает

| Возможность | Метод Sipuni | Где в CRM |
|---|---|---|
| Звонки в журнал в реальном времени | HTTP-события АТС (event 1/2/3) | `POST/GET /api/webhooks/sipuni` |
| Привязка звонка к менеджеру | `short_src_num` / `short_dst_num` / `last_called` | поле «Внутренний номер SIP» у пользователя |
| Запись разговора | `call_record_link` в событии завершения | карточка звонка |
| Звонок в один клик | `callback/call_number` | кнопка «Позвонить» |
| Проверка соединения | `statistic/operators` | «Телефония» → «Проверить соединение» |
| Общий номер → ответственный | функция схемы «HTTP-запрос» | `GET /api/webhooks/sipuni-routing` |
| Личный номер менеджера | `dst_num` входящего | поле «Личный номер» у пользователя |

## Подключение

1. Кабинет Sipuni → «Настройки» → «Интеграция по API» → «Сгенерировать».
   Сохраните ключ.
2. На сервере в `.env`:

   ```bash
   TELEPHONY_PROVIDER=sipuni
   SIPUNI_USER=088282                    # номер кабинета
   SIPUNI_SECRET=<ключ из шага 1>
   SIPUNI_WEBHOOK_TOKEN=$(openssl rand -hex 24)
   ```

   Перезапустите приложение: `./deploy/deploy.sh --no-pull`.
3. Кабинет Sipuni → «Настройки» → «API» → «События на АТС» → «Подключить
   услугу». URL:

   ```
   https://vin2win.online/api/webhooks/sipuni?token=<SIPUNI_WEBHOOK_TOKEN>
   ```

4. В CRM → «Пользователи» каждому менеджеру укажите внутренний номер SIP —
   короткий номер сотрудника в Sipuni (например, `101`).
5. «Телефония» → «Проверить соединение», затем тестовый звонок.

## Номера: личные и общий

**Личный номер** у каждого менеджера настраивается в Sipuni как отдельная схема,
ведущая прямо на его внутренний номер. В CRM этот номер указывается в карточке
пользователя: входящий на него сразу считается звонком этого менеджера.

**Общий номер** распределяет звонки по ответственным:

1. Конструктор → схема общего номера → «+» в самом начале → «Переход звонка» →
   «HTTP-запрос». URL:

   ```
   https://vin2win.online/api/webhooks/sipuni-routing?token=<SIPUNI_WEBHOOK_TOKEN>
   ```

2. Sipuni присылает `GET ?fromnum=&tonum=&dtmf=&label=&time=`, CRM отвечает:
   - клиент есть, ответственный активен и с добавочным —
     `{"choice": 1, "number": "201", "name": "Иван · ООО Ромашка"}`: АТС 15 секунд
     вызывает ответственного, затем идёт по **правой** ветке;
   - иначе — `{"choice": 0}` (и `name`, если клиент известен): **левая** ветка.
3. Обе ветки ведите на общую группу менеджеров: правая — страховка, если
   ответственный не взял трубку, левая — новые клиенты.

Любая ошибка CRM возвращает `choice: 0` — клиент дозвонится в любом случае.

**Кто ответственный.** Назначается в карточке контакта (админ — любого,
менеджер может взять себе свободного клиента). Если ответственного нет, его
закрепляет первый состоявшийся разговор: кто поговорил с клиентом, тот и ведёт.

## Безопасность вебхука

Sipuni не подписывает HTTP-события. Защита — секретный токен в URL: без него
вебхук отвечает 401. Токен не пишется в лог и не показывается в интерфейсе.
Сменили токен — обновите URL в кабинете Sipuni.

Sipuni ждёт в ответ JSON с полем `success`. При некорректных ответах он
приостанавливает отправку, поэтому вебхук всегда отвечает `{"success": …}`.

## Разбор событий

| event | Значение | Статус в CRM |
|---|---|---|
| 1 | начало вызова или перевод | «Дозвон» |
| 3 | ответ | «Разговор» |
| 2 | завершение, `status` = ANSWER / BUSY / NOANSWER / CANCEL / CONGESTION / CHANUNAVAIL | ANSWER → «Завершён»; входящий без ответа → «Пропущен»; исходящий → «Занято» / «Без ответа» / «Отменён» / «Ошибка» |
| 4 | промежуточное завершение при переводе с подсказкой | пропускается |

Внутренние звонки между сотрудниками (обе стороны `*_type=2`) в журнал не
пишутся.

Порядок доставки не гарантирован, а при дозвоне на группу приходят события по
каждому плечу. Поэтому статус не откатывается: состоявшийся разговор не
превращается обратно в «Пропущен» из-за отказа соседнего плеча
(`canTransition` в `lib/telephony/ingest.ts`).

## Подпись исходящих запросов

`hash = md5(значения параметров через «+» в порядке из документации + user + secret)`.

Для `callback/call_number` порядок: `antiaon`, `phone`, `reverse`, `sipnumber`.

## Что проверить на живом кабинете

Формат событий и методы взяты из документации и открытых клиентов API. На
живом кабинете при первом подключении проверьте:

- ответ `callback/call_number`: в каком поле приходит id заказа звонка (сейчас
  ищутся `callId`, `call_id`, `id`; он нужен только для аудита);
- доступна ли ссылка `call_record_link` без авторизации — если нет, запись
  нужно будет проксировать через `statistic/record`;
- поля событий при звонке через схему с группой: из `last_called` берётся
  первый номер.
